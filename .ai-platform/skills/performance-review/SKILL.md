# performance-review

코드/쿼리/네트워크/렌더링 병목을 찾아 개선안을 제시한다.

## 입력

- 성능 목표
- 트래픽/데이터 규모
- 측정 결과
- 코드/쿼리
- 인프라 제약

## 산출물

- 병목 후보
- 측정 방법
- 개선안
- 리스크
- 재검증 기준

## 작업 절차

1. 목표 지표를 먼저 확정한다.
2. 추측보다 측정 지점을 제시한다.
3. DB/API/캐시/렌더링 병목을 분리한다.
4. 개선 전후 검증 방법을 쓴다.

## 품질 기준

- 측정 없이 최적화하지 않는다.
- 캐시 무효화 리스크를 기록한다.
- 복잡도 증가 비용을 평가한다.

## 사용 원칙

- 내부 개발 도구용 스킬이다. 외부 공개나 public marketplace 배포를 전제로 하지 않는다.
- 프로젝트의 기존 구조, 회사 표준, 보안 정책, Definition of Ready/Done을 우선한다.
- 모호한 입력은 가정하지 말고 필요한 확인 질문과 누락 문맥을 먼저 정리한다.
