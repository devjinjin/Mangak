# code-review Review Checklist

## 입력 확인

- diff
- 요구사항
- 테스트 결과
- 관련 표준
- 리스크

## 리뷰 절차

1. 요구사항 충족 여부를 먼저 본다.
2. 버그/보안/성능/테스트 순서로 점검한다.
3. 수정 제안은 파일/라인 단위로 구체화한다.

## 판정 기준

- 취향을 필수 수정처럼 말하지 않는다.
- 테스트 실행 여부를 확인한다.
- 보안 위험을 별도 표시한다.

## 결과 형식

- Summary: 변경/검토 대상 한 줄 요약
- Must Fix: 병합/배포 전 필수 수정
- Should Improve: 품질 개선 권장 사항
- Evidence: 근거 파일, 테스트, 로그, 측정값
- Verification: 수정 후 다시 실행할 명령
