# 모호성 판단 스킬 (프로그램 개발 기획)

사용자 요청을 받으면 **무조건 개발을 시작하지 않고** 요청의 모호성을 먼저 판단한다 (계획서 8.1).
모호하면 질문 목록을 생성하고, 명확하면 "진행 가능" 판정과 함께 확정된 전제를 정리한다.

## 모호성 판단 기준 (계획서 8.2 - 다음 중 하나라도 불명확하면 질문)

1. **플랫폼 유형**: 웹 / 모바일 / 데스크톱 / API 서버 중 무엇인가?
2. **시스템 성격**: 관리자 시스템인가, 사용자 서비스인가?
3. **기술스택**: Spring Boot / 전자정부프레임워크 / .NET / Next.js / Python 중 선택이 필요한가?
4. **DB**: 종류가 정해져 있는가?
5. **배포 환경**: IDC / 클라우드 / 내부망 중 어디인가?
6. **규제 제약**: 공공기관 / 금융 / 사내망 제약이 있는가?
7. **보안 요구사항**: 명확한가?
8. **하네스 문서**: 회사 하네스 문서 적용 범위가 명확한가?
9. **범위와 완료 기준**: 무엇이 되면 "완료"인가? 제외 범위는?
10. **기존 자산**: 참고할 기존 기획서/화면/API/DB 문서가 있는가? (계획서 10장)

## 판정 절차

1. 요청 문장에서 위 10개 기준 각각을 [명확 / 불명확 / 해당 없음]으로 분류한다.
2. "불명확" 항목이 1개 이상이면 → **판정: 질문 필요**
   - 항목별로 구체적 질문을 만들되, 선택지를 제시한다 (예: "DB는 PostgreSQL, MySQL, Oracle 중 어느 것을 사용하나요?").
   - 질문은 .ai-platform/platform-decision/questions.md 형식으로 정리한다 (계획서 8.3).
3. 모두 "명확/해당 없음"이면 → **판정: 진행 가능**
   - 확정된 전제를 표로 정리하고 selected-platform.md 초안을 제안한다.

## 출력 형식

```
## 모호성 판정: [질문 필요 | 진행 가능]

| # | 기준 | 판정 | 근거 |
|---|------|------|------|
| 1 | 플랫폼 유형 | 명확 | "웹 관리자 페이지"라고 명시됨 |
...

### 확인 질문 (질문 필요 시)
1. ...
```

## 품질 기준

- 추측으로 기준을 "명확"으로 판정하지 않는다. 근거 문장이 요청에 없으면 "불명확"이다.
- 질문은 한 번에 모아서 제시한다 (반복 질문으로 사용자를 지치게 하지 않는다).
