# error-memory

반복되는 빌드/테스트/운영 오류와 해결 절차를 재사용 가능하게 정리한다.

## 입력

- 오류 메시지
- 재현 절차
- 환경 정보
- 원인
- 해결 명령

## 산출물

- 오류 패턴
- 원인 분석
- 해결 절차
- 예방 체크

## 작업 절차

1. 원문 오류와 환경을 보존한다.
2. 근본 원인과 임시 우회를 구분한다.
3. 다음 재발 시 확인 순서를 쓴다.

## 품질 기준

- 스택트레이스를 과도하게 장기 저장하지 않는다.
- 비밀값을 마스킹한다.
- 검증된 해결책만 기록한다.

## 사용 원칙

- 내부 개발 도구용 스킬이다. 외부 공개나 public marketplace 배포를 전제로 하지 않는다.
- 프로젝트의 기존 구조, 회사 표준, 보안 정책, Definition of Ready/Done을 우선한다.
- 모호한 입력은 가정하지 말고 필요한 확인 질문과 누락 문맥을 먼저 정리한다.
